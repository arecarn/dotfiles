### Ticket References

An ID or number alone does not tell the reader what a ticket is, so name it.

- **Give the title with the ID.** Whenever you list or mention a ticket (a Jira
  issue, Problem Report, SCR or task; a GitHub issue or pull request), put its
  summary or title next to the identifier, for example
  `NGAVPR-8659 (Card F HLSR Verification is unhealthy)` or
  `#35 (Herdr mishandles emoji presentation sequences)`. Jira calls it the
  summary, GitHub the title.
- **Look it up, never guess.** If you do not have the summary or title, fetch it
  before writing (Jira tools for Jira keys, `gh issue view` / `gh pr view` for
  GitHub).
- **Every mention, not only the first.** This applies to messages, reports,
  lists and tables alike. Identifiers inside code, branch names, commit-message
  prefixes and issue-closing keywords stay as the project requires.
- **Use the platform's own words.** Say "pull request" for GitHub and "issue"
  for both; do not carry GitLab terms such as "merge request" over to GitHub.
